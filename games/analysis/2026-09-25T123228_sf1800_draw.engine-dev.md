## 2. Diagnosis — root causes, ranked by cost

**A. Eval has no positional knowledge beyond material + tapered PST.** 7 of 9 flagged mistakes (plies 11, 25, 27, 29, 57, 97, 125) are moves where material stays equal but the position gets structurally worse — weakening f3, repeated queenside pawn pushes instead of Bg2/knight development, a passive queen move over a pawn break, a bishop shuffle over king centralization. This is the classic fingerprint of a shallow static eval: with no king-safety, mobility, pawn-structure, or piece-activity terms, every roughly-equal-material option looks the same to the search, so it effectively picks close to arbitrarily among them. This also explains the "41 cp/move" average bleed across the whole game — a steady drip, not just the occasional spike.

**B. No search infrastructure to buy depth.** No transposition table, no hash-move ordering, no null-move pruning, no PVS/LMR, no killer/history heuristics — move ordering is recomputed from scratch via static MVV-LVA at every node with no memory across the tree or across iterative-deepening iterations. This caps effective depth in the 5s budget and is the direct cause of the two clearly tactical blunders: ply 33 (Qxd5 walks into a fork whose full point is 3 plies deep) and ply 83 (Bc2 misses a forced sequence starting with Qg1+).

**C. No check extensions / no king-safety search bias.** Both tactical blunders above are specifically "into-check" continuations. A cheap 1-ply check extension plus even a crude king-danger eval term would very likely flip both at the current search depth — and ply 83 alone is the single costliest mistake of the game (-212 immediately, -261 more the next move).

## 3. Improvement plan

Ordered by expected Elo gain per hour of work. Items already in `JOURNAL.md`'s Plan queue are marked **[already queued]**; the rest are new, driven by this game's specific blunder pattern.

1. **Transposition table + hash-move ordering** [already queued]. **~+80–120 Elo, ~1.5–2h.**
   Fixed-size array of `TTEntry { key: u64, depth: i8, score: i32, flag: Exact|Lower|Upper, best: Option<Move> }`, indexed by `hash(pos) & (SIZE-1)` (reuse the existing `hash()` in `main.rs`, already computed for repetition — don't recompute). Probe at the top of `negamax()` for a cutoff and as the first move tried in `ordered`; store on exit. Depth-preferred or always-replace scheme is fine at this stage.
   Test: round-trip unit test (store then probe returns the same entry); A/B gauntlet (`uv run python -m arena.gauntlet bin/destroyer bin/destroyer-<old>`); confirm `info depth` climbs faster for the same time budget on a fixed FEN.

2. **Opening book, ~8–10 plies (White repertoire), generated by full-strength Stockfish** [already queued]. **~+40–80 Elo, ~1h.**
   This is exactly what plies 1–15 of this game needed: a3/b3/c3/d3/e3/f3/g3/h3 instead of central development. Load a small `zobrist -> Vec<UciMove>` table (keyed the same way as `hash()`) built offline with `bin/stockfish`; in `main()`'s `Some("go")` handling, check the book before constructing `Search` and print `bestmove` immediately on a hit.
   Test: `go` on a book position returns instantly with the book move; play a couple of `uv run arena --elo 1320 --time 0.2` smoke games and confirm the first ~8 moves are the book line, not edge-pawn pushes.

3. **Eval: mobility + king safety + bishop pair + basic pawn structure** (extends already-queued item 7 "mop-up/passed pawns/king safety"; mobility and bishop-pair are new, motivated directly by this game). **~+40–70 Elo, ~2h.**
   7 of 9 flagged mistakes in this game are moves where material stayed equal but the position got structurally worse — the eval literally can't see why. Add tapered terms in `eval.rs::evaluate()`, combined into the existing `mg[side]`/`eg[side]` accumulators before the phase blend:
   - *Mobility*: for each non-pawn piece, `shakmaty::attacks::attacks(sq, piece, occupied).count()` minus own-occupied squares, ~2–4 cp/square.
   - *Bishop pair*: +30 mg / +50 eg if a side holds both bishops.
   - *King safety*: count enemy attackers on the 3×3 zone around the king via `pos.board().attacks_to(sq, them, occupied)`, plus a missing-pawn-shield penalty in front of a castled king.
   - *Pawn structure*: doubled pawns (~-10 to -20 cp) and isolated pawns (~-15 cp), both simple same-file/adjacent-file bitboard checks.
   Test: extend the existing `#[cfg(test)] mod tests` in `eval.rs` (which already has `central_pawn_beats_edge_pawn`, `developed_knight_beats_rim_knight`) with directed cases from this game, e.g. `evaluate(after_Bg2) < evaluate(after_b4)`; then A/B gauntlet.

4. **Check extensions (capped) + SEE-pruned quiescence + `score mate N`** [already queued]. **~+30–50 Elo, ~1.5h.** Targets this game's two genuinely tactical blunders directly: ply 33 (Qxd5 → Nd3+ fork) and ply 83 (Bc2 missing Qc3 before Qg1+) are both "walks into a check-heavy tactic 1–3 plies past the horizon."
   In `negamax()`: `let ext = if pos.is_check() { 1 } else { 0 };` on the recursive call, capped by a per-line extension counter to bound blowup. SEE: implement `fn see(pos: &Chess, m: &Move) -> i32` walking the exchange least-valuable-attacker-first via `pos.board().attacks_to(target, color, occupied)`; in `quiesce()`, require `see(pos, &m) >= 0` for the `m.is_capture()` branch only (never gate the `in_check` branch on it). `score mate N`: in `best_move()`'s reporting line, when `alpha.abs() > MATE - MAX_PLY`, emit `info depth {depth} score mate {..} nodes {}` instead of `score cp` — arena's `play.py` already calls python-chess's `score.relative.score(mate_score=10_000)`, which expects this natively.
   Test: directed mate-in-2 FEN unit test asserting `score mate 2`; A/B gauntlet; replay this game's ply33/ply83 FENs through the new binary at `go movetime 5000` and confirm Qxd5/Bc2 are no longer chosen.

5. **Null-move pruning** [already queued]. **~+30–50 Elo, ~1h.**
   In `negamax()`: `if depth >= 3 && !pos.is_check() && has_non_pawn_material(pos, pos.turn())`, try a reduced-depth search (R=2) after flipping the side to move (shakmaty has no built-in null move; add a small helper that clones the `Setup`/board with turn flipped and en passant cleared). Guard against zugzwang-prone low-material endgames (this game's own K+B vs K+R ending is exactly that case) by requiring at least one non-pawn piece for the side to move.
   Test: gauntlet; a small suite of K+P zugzwang FENs to confirm null-move is disabled there (correctness, not Elo).

6. **Killer moves + history heuristic** [already queued]. **~+20–35 Elo, ~1h.**
   Add `killers: [[Option<Move>; 2]; MAX_PLY as usize]` and `history: [[i32; 64]; 12]` to `Search`; use as ordering tiebreak after the TT move and MVV-LVA in the `ordered.sort_by_key` calls in `negamax`/`quiesce`; update on a beta cutoff for quiet (non-capture) moves.
   Test: gauntlet; confirm node count drops at equal depth vs. the pre-killer baseline on a few fixed FENs.

7. **PVS + LMR** [already queued]. **~+30–50 Elo, ~1.5–2h** — do this after TT + killers so re-search cost stays manageable.
   In `negamax()`, search the first move full-window/full-depth; search the rest with a null window `(-alpha-1, -alpha)` and a reduced depth for late, quiet, non-check moves, re-searching full window/depth on fail-high.
   Test: gauntlet; verify PVS+LMR doesn't change `bestmove` on a set of tactical test FENs (should only change nodes searched, not the answer).

8. **Aspiration windows around the previous iteration's score** (new, not yet in the JOURNAL queue — cheapest item here). **~+5–15 Elo, ~20–30 min.**
   In `best_move()`'s depth loop, once `depth >= 4`, start with `alpha = prev_score - 50, beta = prev_score + 50` instead of `-INF`/`INF`; widen and re-search on fail-low/fail-high. Cheap enough to slot in alongside item 7's work in the same session.
   Test: gauntlet; confirm the score reported at each depth matches a full-window search on a handful of fixed positions (guards against a narrow window silently returning a wrong score).

9. **Endgame king activity + passed pawns** (remainder of already-queued item 7 not covered by item 3's king-*danger* term). **~+15–25 Elo, ~45 min** — folds naturally into item 3's implementation pass.
   Tapered by `eg_phase` in `eval.rs`: bonus for king proximity to passed pawns/the center, and a passed-pawn bonus scaled by rank. Targets ply 125 (Bb1 instead of Kd3) directly, where the existing `EG_KING` PST alone wasn't enough to make king centralization beat a purposeless bishop move.
   Test: directed unit test — `evaluate` must prefer a centralized king over an edge-square king in an otherwise-identical pawn-only ending; then gauntlet.

## 4. Risks

- **Check extensions** without a hard cap on cumulative extensions per line can blow the 5s budget on lines with repeated checks (perpetual-check-like sequences). Cap total extensions per line (e.g. 6–8 ply) and consider tightening the deadline check from `self.nodes & 2047` to `& 1023` once extensions/null-move/LMR are in, since a single branch can now run longer between node-count checkpoints.
- **Null-move pruning** in zugzwang-prone, low-material endgames (exactly this game's K+B vs K+R ending) can produce false cutoffs. Gate it on "side to move has at least one non-pawn, non-king piece" (or skip below a material threshold), and never apply it while in check.
- **Transposition table correctness**: (1) always verify a TT-stored move is still in the current legal move list before playing/ordering it — a 64-bit key collision is rare but real; (2) mate scores stored in the TT must be ply-adjusted on store/retrieve (classic bug: a mate score found N plies from a TT-hit node is not the same distance from the root) — get this wrong and `bestmove`/`score mate N` can misreport, or worse, mis-rank a cutoff.
- **`score mate N` output**: arena's engine wrapper (`arena/play.py`) already calls `score.relative.score(mate_score=10_000)` via python-chess, which natively expects `score mate N` — so emitting it is safe and in fact already-expected, not a new risk. Just verify sign/parity with a directed unit test (mate-in-2 FEN → `score mate 2`, not `-2` for the side about to deliver it) since `--abort-hopeless` logic reads this value.
- **SEE-pruned quiescence**: the bad-capture filter must apply only within the `m.is_capture()` branch of the existing `filter(|m| in_check || m.is_capture() || m.is_promotion())` in `quiesce()` — never let it suppress the "all moves when in check" branch, or the search can return a static eval from inside check and misjudge mate/stalemate.
- **Opening book**: only ever short-circuits `go` (returns `bestmove` without searching); it must not bypass or desync the existing `history`/repetition tracking in `parse_position`/`main()`, which is driven by the UCI `position ... moves ...` list the GUI/arena sends back regardless of whether we searched or booked the previous move — this should fall out for free, but add a test that plays a full book line through the `position`/`go` loop and checks `history.len()` matches ply count.
- **Time management is untouched by all of the above** — `think_time()` and `MOVE_TIME` in `arena/play.py` must not be touched by any of this work; the only way any of these features could violate the 5s/move rule is via the extension-cap and deadline-check-cadence points above, not via the time budget itself.
